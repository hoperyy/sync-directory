Node.js CLI + API

Sync folders
with Node.js.

sync-directory copies a local source folder to a target. Run once, or keep it updated as files change.

Copy by default · Optional hardlinks · CommonJS & ESM

Sourcesrc/├ index.js└ assets/└ logo.svg
→
Targetmirror/├ index.js└ assets/└ logo.svg

One source. One target. Same file paths.

1

Install

For the command line

npm install --global sync-directory

For a Node.js project

npm install sync-directory

The source must exist. The target is created if needed. Relative and absolute paths both work.

2

Run the CLI

syncdir <source> <target> [options]

Copy once

Sync the folder, then exit.

syncdir ./src ./mirror

Keep watching

Apply later source changes too.

syncdir ./src ./mirror \
  --watch

Create hardlinks

Share file data on one filesystem.

syncdir ./src ./mirror \
  --hardlink

Use a dedicated target: matching files can be overwritten, and watching also propagates source deletions.

All CLI flags
Copy is the default; other behaviors are off unless enabled.

3

Use the API

CommonJS

const syncDirectory = require('sync-directory');

syncDirectory('./src', './mirror');

ES modules

import syncDirectory from 'sync-directory';

syncDirectory('./src', './mirror');

Import from the package root. Pass configuration as the third argument.

Async API, callbacks & stopping a watcher 
import { async as syncDirectoryAsync } from 'sync-directory';

const watcher = await syncDirectoryAsync('./src', './mirror', {
  watch: true,
  afterEachSync({ eventType, relativePath }) {
    console.log(eventType, relativePath);
  },
});

// When watching is no longer needed:
await watcher.close();

syncDirectory() and .sync() return a watcher with watch: true, otherwise undefined. The async API returns a Promise of the same result; it awaits initial scanning and callbacks, while file copies still use synchronous operations.

afterEachSync also receives nodeType, srcPath, and targetPath. Events: init:copy, init:hardlink, add, change, unlink, unlinkDir, addDir.

4

Choose your options

A typical watch setup

syncDirectory('./src', './mirror', {
  watch: true,
  exclude: ['node_modules', '.git'],
});

String filters match substrings, not globs.

watch
Keep syncing changes. Default: false.
exclude
Skip matching paths. Default: no exclusions.
type
'copy' (default) or 'hardlink'.
skipInitialSync
Watch only later changes. Default: false.
deleteOrphaned
Clean initial target leftovers. Default: false.
Copy vs hardlink: which should I use?

Copy — the usual choice

Separate file contents. Better when a bundler or dev server watches the target. Uses disk space for the copied files.

Hardlink — a shared file

Both paths share data and must be on the same filesystem. Editing either can affect both; some target watchers miss changes.

Use copy for reliable watching of newly created or replaced files. Hardlink watch handlers do not always create or restore links.

5

Before you sync

Does it sync in both directions?

No. Changes flow from source to target. It does not merge independent edits. Hardlinks share data, so editing either link can affect both.

When are target files deleted?

Initial sync keeps extra target entries unless deleteOrphaned: true is set. While watching, source deletions remove matching non-excluded target paths regardless of that option.

Can I watch without copying the folder first?
syncdir ./src ./mirror --watch --skipInitialSync

Existing unchanged entries are skipped; subsequent source changes are processed.

Compatibility & implementation notes

Based on the source implementation; check your installed version for changes.

  • ESM: import 'sync-directory'. The package exports map does not expose 'sync-directory/index.mjs'.
  • Symlinks: CLI --symlink sets supportSymlink, but initial hardlink processing reads staySymlink. That API option creates a target symlink to the source path.
  • Hardlink watching: with stayHardlink: true, handlers do not create or relink files. New files and saves that replace source inodes may not stay linked.
  • Filters: predicates receive paths relative to the scanned source or target; chokidar may also pass absolute paths. Allow watched exceptions and their parents in the exclusion predicate.
  • New directories: watched addDir events may copy descendants recursively without filtering each child, even with nodeep.
  • Errors: initial onError callbacks are not awaited. Some low-level failures are caught internally.
