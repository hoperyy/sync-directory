A small tool for your Node.js workflow

Sync two directories.

sync-directory copies or hardlinks files from a source directory to a target directory. Run a one-time sync, or watch for file changes with the syncdir CLI and the Node.js API.

01

Start with a simple sync

Use two local paths: the source you want to read and the target you want to update. Both relative and absolute paths work. The source directory must already exist; the target directory is created if needed.

In your terminal

npm install --global sync-directory

# Copy the source tree once
syncdir ./src ./mirror

# Copy it, then watch for changes
syncdir ./src ./mirror --watch

In your Node.js project

npm install sync-directory
const syncDirectory = require('sync-directory');

syncDirectory('./src', './mirror');

Good for local development assets, build scripts, and tooling that needs a source-to-target folder sync.

Choose a dedicated target folder. Syncing can overwrite matching target files. Watch mode also propagates source deletions. deleteOrphaned controls cleanup during the initial sync; it does not disable deletions while watching.

02

The syncdir CLI

Install globally to make syncdir available in your shell. By default, it copies recursively once and exits. Add --watch to keep it running.

syncdir <from> <to> [options]

# Ignore dependencies and a lockfile
syncdir ./src ./mirror --watch --exclude node_modules package-lock.json

# Create hardlinks during the initial sync
syncdir ./src ./mirror --hardlink

# Watch an already populated target without an initial copy
syncdir ./src ./mirror --watch --skipInitialSync

03

The Node.js API

Call syncDirectory(srcDir, targetDir, options) for synchronous work. Use the asynchronous export when you want to await the initial sync or an asynchronous callback.

CommonJS

const syncDirectory = require('sync-directory');
const { async: syncDirectoryAsync } = require('sync-directory');

syncDirectory('./src', './mirror');

ES modules

import syncDirectory, {
  async as syncDirectoryAsync,
} from 'sync-directory';

syncDirectory('./src', './mirror');

Import from the package root. Its exports map chooses the CommonJS or ESM entry point; the older sync-directory/index.mjs import shown in the README is not an exported package subpath.

Choose the function that fits your workflow

Run something after each synced entry

await syncDirectoryAsync('./src', './mirror', {
  async afterEachSync({ eventType, nodeType, relativePath, srcPath, targetPath }) {
    console.log(eventType, relativePath);
    // Await your own work here, for example updating a build manifest.
  },
});

The callback receives eventType, nodeType (file or dir), the relative path, and the source and target paths. Events include init:copy, init:hardlink, add, change, unlink, unlinkDir, and addDir.

04

Watch changes and filter paths

Keep a local target up to date

watch: true starts a chokidar watcher after the initial sync. Keep the returned watcher if you need to stop it later. Awaiting the async function finishes the initial sync; it does not wait for watching to end.

const watcher = await syncDirectoryAsync('./src', './mirror', {
  watch: true,
  exclude: ['node_modules', '.git'],
  chokidarWatchOptions: {
    awaitWriteFinish: {
      stabilityThreshold: 2000,
      pollInterval: 100,
    },
  },
});

// When your script no longer needs to watch:
await watcher.close();

Exclude entries, with specific exceptions

exclude and forceSync accept a string, regular expression, predicate, or array of matchers. Strings match substrings. Library filters use paths relative to the scanned source or target; they can start with a path separator. In watch mode, chokidar can also pass absolute paths to the exclusion predicate. Normalize separators rather than relying on a trailing slash.

syncDirectory('./src', './mirror', {
  exclude: ['.map', '.log'],
  forceSync: 'important.log',
});

forceSync wins when the library evaluates both filters for an entry, so this initial sync includes important.log. You can also keep a package inside an excluded directory during the initial sync:

syncDirectory('./src', './mirror', {
  exclude: 'node_modules',
  forceSync: 'node_modules/keep-this-package',
});

Watch filters have extra limits. Chokidar can ignore a path before forceSync runs. For watched exceptions, allow the entry and its parent directories in your exclusion predicate. New-directory events can also copy descendants recursively without filtering each child, so verify the behavior for your folder layout.

API options, at a glance

Pass these as the third argument. Start with the defaults and add the behavior your workflow needs.

cwdprocess.cwd()
Base directory for resolving relative source and target paths.
type'copy'
'copy' or 'hardlink'. Compare the two modes before enabling hardlinks.
watchfalse
Watch for later source changes using chokidar. The function returns a watcher, directly or through a Promise.
chokidarWatchOptions{}
Options passed to chokidar, such as awaitWriteFinish. Custom options override the library's watcher defaults.
skipInitialSyncfalse
Skip the initial directory sync. Use with watch: true to process subsequent changes; without watching, no sync runs.
deleteOrphanedfalse
During the initial sync, remove target entries absent from the source within the scanned, non-excluded set. Do not rely on it to clean excluded target entries. Source deletions still propagate in watch mode.
excludenull
Skip matching paths. Accepts strings, regular expressions, functions, and arrays of those matchers.
forceSyncnull
Include a matching entry despite an exclusion when both filters are evaluated. Accepts the same matcher types as exclude. See watcher caveats.
nodeepfalse
Scan only first-level entries during the initial sync. Watch mode checks event paths, but a new-directory event can copy its contents recursively.
stayHardlinktrue
Used with type: 'hardlink'. On watched changes, false replaces a target hardlink with a copy. See hardlink limitations.
staySymlinkfalse
Enables symlink handling during the initial hardlink sync. This does not provide general symlink preservation in copy or watch mode.
afterEachSync() => {}
Callback after an entry is processed. The async API awaits it during the initial sync; watch handlers also await it per event.
onErrorthrows an Error
Handles errors surfaced by the sync processor. Initial sync error handlers are not awaited, even by the async API. Some low-level filesystem errors are caught internally, so this callback does not report every failure.
06

Copy or hardlink?

Use copy for the usual development workflow. It creates separate target files and is the package default. This is the better starting point when a bundler or development server watches the target directory.

The default

Copy

Source and target have separate file contents. A one-time sync takes a copy; watch mode updates it after source events. Uses additional disk space for target files.

syncDirectory('./src', './mirror');

For controlled local workflows

Hardlink

Two paths share the same underlying file data. Links require the same filesystem. Editing either link can affect the other, and some target-side watchers miss changes.

syncDirectory('./src', './mirror', {
  type: 'hardlink',
});

Hardlinks can avoid copying file bytes, but check your editor and filesystem behavior before combining them with watching. See the implementation notes for newly created or replaced files.

Where this tool fits

Use sync-directory when local folder syncing belongs inside a Node.js script, plugin, or development workflow. It combines initial sync, path filtering, and a watcher. For remote transfers over SSH, use a tool designed for remote synchronization, such as rsync. For a standalone copy without watching, a filesystem copy function may be enough.

07

A few common questions

Does it sync in both directions?

No. The source drives the target. It does not merge two directories or resolve edits made independently in both trees. Hardlinks share file data, so they need extra care even though the sync workflow remains source-to-target.

Will it remove files from the target?

An initial sync keeps unmatched target entries unless deleteOrphaned: true is set. While watching, a source unlink or unlinkDir event removes the corresponding non-excluded target path regardless of that option.

Can I watch without copying the directory first?

Yes. Set both watch: true and skipInitialSync: true, or use syncdir ./src ./mirror --watch --skipInitialSync. This processes later changes; existing unchanged entries are not initially synced.

Does the async API return the watcher?

Yes. With watch: true, await the function to get a chokidar watcher, then call await watcher.close() when needed. Without watching, the Promise resolves to undefined.

Are exclusion strings glob patterns?

No. A string is a substring match against the path. Use a regular expression or predicate when you need more precise matching, and allow ancestor directories when keeping nested exceptions.

Implementation notes worth checking before you rely on an option

These notes reflect the source implementation reviewed for this guide. Check the repository and your installed version for changes.

  • ESM imports: use 'sync-directory'. The package's export map does not expose 'sync-directory/index.mjs', even though older README examples use it.
  • Symlinks: the CLI's --symlink sets supportSymlink, while initial hardlink processing reads staySymlink. The API option is handled in hardlink mode and creates a target symlink to the source path; it does not preserve all symlink behavior across modes.
  • Hardlink watching: with stayHardlink: true, file event handlers do not create or relink target files. New files and editor saves that replace the source inode may not stay linked. Use copy mode if the target needs to track these changes reliably.
  • Filter exceptions: excluded ancestors can prevent a nested entry from being scanned. Chokidar may also ignore a path before forceSync is evaluated. Allow the exception and its parents in the exclusion predicate.
  • Cleanup: both source and target scans apply exclusion filters, so excluded target files are not reliably removed by deleteOrphaned, despite the README's broader description.
  • Shallow watching: nodeep limits the initial scan and filters nested event paths, but a watched addDir event can copy a new directory recursively without applying exclusions to each descendant.
  • Async and errors: the async API awaits directory scanning and callbacks, but individual copies still call synchronous filesystem functions. Some filesystem failures are caught internally rather than forwarded to onError.
